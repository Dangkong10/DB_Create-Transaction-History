# 동기화 "N건 대기 중" 고착 — 설계서

- 작성일: 2026-09-03
- 상태: **구현 완료** (2026-09-03, 미커밋 · 미배포)
- 증상: 태블릿 A에서 저장한 거래가 태블릿 B에 안 보이고, A의 배지가 `N건 동기화 대기 중`에서 안 내려감

## 1. 목적

세션(로그인 토큰)이 끊겼을 때
(a) 미동기화 거래가 **삭제되지 않게** 하고,
(b) 화면에 "대기 중"이 아니라 **"로그인 필요"**로 정직하게 표시해
사용자가 스스로 복구할 수 있게 한다.

## 2. 확정된 원인

태블릿 절전 → 깨어남 → 액세스 토큰 만료 + 와이파이 재연결 지연 → 토큰 갱신 실패 → `getSession()` null.

이때 두 가지가 동시에 일어난다.

1. **조용한 중단** — `lib/sync-manager.ts:191-192`
   ```ts
   const session = await getSession();
   if (!session) return;   // 로그 한 줄 없이 종료
   ```
   큐는 그대로, `retryCount`도 안 오름 → 상태가 `error`가 아닌 **`idle` + pendingCount > 0**
   → 배지는 `sync-status-badge.tsx:113`의 `N건 동기화 대기 중`을 영구 표시.
   30초 타이머가 매번 같은 지점에서 return → "동기화 중… → 대기 중" 왕복.

2. **데이터 손실 경로** — `components/AuthGuard.tsx:119`가 `!session`을 곧바로 로그아웃으로 단정
   → 팝업의 "로그인 화면으로"가 `clearPendingSync() + wipeAllLocalData()` (`AuthGuard.tsx:53`)
   → 서버로 못 올라간 거래가 **영구 삭제**.

부수 효과: 같은 세션 문제로 `pullFromServer()`도 throw → `history.tsx:147`이 로컬 fallback
→ 다른 태블릿 거래가 안 보임.

## 3. 범위

### 고칠 것
1. **로그아웃 시 로컬 소거 제거** (`AuthGuard.tsx:53`, `:62`) — 삭제만 하는 수정
2. **`SyncState`에 `auth` 추가** (`sync-manager.ts`, `sync-status-badge.tsx`) — 배지 문구 + 탭하면 재시도/로그인
3. **오프라인을 로그아웃으로 오판하지 않기** (`AuthGuard.tsx:119`) — `navigator.onLine === false`면 배너만

### out of scope
- 재시도 백오프(지금은 30초 고정) — 세션이 살아있으면 30초로 충분
- MAX_RETRY 도달 항목의 별도 관리 화면("미전송 함") — 이번 증상과 무관, idea-box로
- `pullFromServer` 증분 동기화(idea-box #6) — 별개 주제
- `updateTransactionOffline` / `deleteTransactionOffline` — 현재 UI에서 호출되지 않는 죽은 경로

## 4. 구조 (수정 3개)

### ① 로그아웃 시 로컬을 지우지 않는다 (필수·삭제만)

`AuthGuard.tsx` `handleSignedOut`:
- `onConfirm`에서 `clearPendingSync(), wipeAllLocalData()` 제거 → `goToLogin()`만
- pending 0일 때의 `wipeAllLocalData()` (`:62`)도 제거
- 팝업 문구 변경:
  - before: `이 내용은 저장되지 않습니다. 계속하시겠습니까?`
  - after: `다시 로그인하면 이어서 전송됩니다.`
- `lib/syncQueueCleaner.ts`의 `clearPendingSync`는 호출자가 사라지므로 함께 삭제
  (`getPendingSyncCount`는 계속 사용)

**남의 데이터가 기기에 남을 위험은?** 계정 전환 wipe(`AuthGuard.tsx:94`, onAuthStateChange)가 이미 담당.
다른 user.id로 로그인하면 그때 지워진다. 로그아웃만으로 지울 이유가 없다.

### ② "대기 중" → "로그인 필요"

`sync-manager.ts`
- `SyncState`에 `'auth'` 추가
- 모듈 스코프 `let authFailed = false`
- `if (!session) { authFailed = true; return; }`, 세션 확보 시 `authFailed = false`
- `emitStatus()`의 우선순위: `offline` → `syncing` → **`auth`** → `error` → `idle`

`sync-status-badge.tsx`
- `auth` 상태 config 추가: 빨강 계열 + `로그인 필요 — N건 미전송`
- 배지를 `Pressable`로 감싸 탭 시 `manualSync()` 호출 (이미 `useSync`가 반환하는데 아무 데서도 안 씀)

### ③ 오프라인 오판 방지

`AuthGuard.tsx` — visibilitychange 핸들러와 **앱 시작 시 세션 확인** 두 곳 모두.
(시작 시점도 같은 오판을 하고 있었다. 여기서 로그인 화면으로 밀어내면 오프라인 입력 자체가 막힌다.)
```ts
if (!session) {
  if (Platform.OS === 'web' && !navigator.onLine) { setStaleSession(true); return; }
  handleSignedOut();
}
```

## 6. 검증

- **자동**: `lib/sync-manager.test.ts` 에 케이스 2개
  1. 세션 null → 큐 길이 불변 + 상태 `auth`
  2. 세션 복귀 → 같은 큐가 전송되고 pendingCount 0
- **수동**(태블릿 실기기, 데스크톱 크롬으로 리허설)
  1. 오프라인 전환 → 거래 저장 → 배지 `오프라인 — 1건`
  2. DevTools에서 auth 토큰 삭제 → 온라인 복귀 → 배지가 **`로그인 필요 — 1건 미전송`**
  3. 재로그인 → 자동 전송 → 배지 `동기화 완료` → 다른 기기에서 pull 시 보임
  4. 2번 상태에서 로그인 화면으로 이동 → **IndexedDB에 거래가 남아있는지** 확인 (핵심)

## 8. 배포 순서 (중요)

①을 배포하기 전까지 현재 빌드의 "로그인 화면으로" 버튼은 여전히 삭제 버튼이다.
따라서 **①을 먼저 배포**하고, 그 다음 태블릿을 재로그인시킨다.
급하면 배포 전이라도 "앱 유지 → 배너의 지금 로그인하기" 경로는 안전(소거 호출 없음).
